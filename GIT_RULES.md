# GIT_RULES.md — Leak Desk (C21) team rules

Read this before every commit and every push. If a commit breaks a rule, fix it before pushing.

## Rule 1 — No AI attribution anywhere in the repo

- Commit author and committer must be the team member's own name and email. Set once per machine:
  `git config user.name "Your Name"` and `git config user.email "you@example.com"`.
- No `Co-authored-by:` trailers that name an AI tool. No "Generated by", "Written with", "Assisted by" lines in commit messages, PR descriptions, code comments, README, docs, or file headers.
- Before pushing, run: `git log --format='%an <%ae>%n%b' origin/main..HEAD | grep -iE 'claude|copilot|gpt|openai|anthropic|co-authored-by'` — output must be empty.
- If you use an AI coding tool, turn off its auto-attribution (for example, disable any "add co-author trailer" or "attribution" setting) before your first commit.
- CI check: `.github/workflows/lint-commits.yml` fails the PR if any of those words appear in commit messages, trailers, or author fields.

## Rule 2 — Short commit messages

- Format: `<area>: <what changed>` in 50 characters or fewer, imperative mood, no full stop.
- Good: `engine: add recovery netting`, `web: ledger reconcile badge`, `api: 422 on bad schema`.
- Bad: long paragraphs, emojis, ticket dumps, "fixed stuff", "final final".
- Areas: `api`, `engine`, `web`, `data`, `tests`, `infra`, `docs`, `ci`.
- One logical change per commit. Body text only when the why is not obvious; keep it to two lines.

## Rule 3 — Branches and merges

- `main` is always demo-able. Nobody pushes to `main` directly.
- Branch name: `feat/<area>-<short>` or `fix/<area>-<short>`, for example `feat/engine-scenario`.
- Open a PR, one reviewer from the team, CI green, then **squash-merge**. The squash title follows Rule 2.
- Rebase on `main` before opening the PR; resolve conflicts on your branch, not on `main`.
- Delete the branch after merge.

## Rule 4 — What never gets committed

- `.env`, API keys, AWS credentials, `*.pem`, tokens. `.env.example` only.
- `node_modules/`, build output (`dist/`, `build/`), uploaded data, logs.
- The original `data/C21/fixture.json` is read-only: never edit it, add rows only in `data/C21_extended.json` with `"synthetic": true`.

## Rule 5 — Every PR must carry

- Which must-have or check it serves (for example "Check 2").
- How it was verified: test name or manual steps.
- One line in `README.md` contributor section if it adds a new component (name → component).

## Rule 6 — Checkpoints

- Hour 4, 8, 10, 11, 13: everything intended for that gate is merged to `main` and `make check` passes.
- If `main` is red, fixing it comes before any new feature.

## Pre-push checklist (copy into your terminal habit)

```
git fetch origin && git rebase origin/main
git log --format='%an <%ae>%n%s%n%b' origin/main..HEAD | grep -iE 'claude|copilot|gpt|openai|anthropic|co-authored-by'   # must print nothing
git log --oneline origin/main..HEAD   # every subject ≤ 50 chars, area prefix
npm test
git push -u origin <branch>
```
