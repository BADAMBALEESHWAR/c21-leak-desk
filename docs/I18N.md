# UI languages

The web app shows its UI chrome in English (default), Hindi or Telugu.

## How it works

- `web/src/i18n/index.ts` sets up i18next with `react-i18next`. The strings live in `en.json`, `hi.json` and `te.json`, and every key exists in all three files. A missing value falls back to English.
- The language comes from `localStorage['lang']` (`en`, `hi` or `te`; anything else means English) and is set on `<html lang>`.
- The switcher at the bottom of the sidebar calls `setLanguage(lng)`, which saves the choice and re-renders at once. The landing page follows the saved choice.
- Numbers use `localeFor(lng)` (`en-IN`, `hi-IN`, `te-IN`) with Latin digits and Indian grouping in all three. The `₹` prefix and the `−` minus are the same in every language.
- Fonts: Inter, then Noto Sans Devanagari and Noto Sans Telugu (`tokens.css`, linked from the three HTML pages). Hindi uses line-height 1.55 and Telugu 1.6.
- Translated: UI chrome only (navigation, titles, table headers, main buttons, status pills). Not translated: data fields, order ids, channel and product names, CSV headers, the public checks, long explanations, tooltips and API messages.
- English accessible names must stay as they are, because `scripts/ui-smoke.mjs` finds controls by them.

## Adding a key

1. Add the key to `en.json`, `hi.json` and `te.json` in the same place.
2. In a component, use `const { t } = useTranslation();` and then `t('section.key')`. For mid-sentence lower case, use `lower(t(...))` from `web/src/i18n`. For counts, use plural keys (`key_one`, `key_other`) with `t('key', { count })`.
3. If you don't have a checked translation yet, put the English text in `hi.json` and `te.json` and note the key under Status.
4. Run `npm test`. `tests/i18n.test.tsx` checks the sidebar in all three languages and the switcher.

## Status

Every key has Hindi and Telugu text. A native speaker should still review them, especially the newer ones: the `nav` hints, `actions`, `common`, `topbar`, `import`, the newer `ledger`, `status`, `leaks`, `scenario` and `decision` keys, and `landing`.

These stay the same in all three files on purpose: `brand` (Profyn), `lang.en`, `lang.hi` and `lang.te` (each language is named in its own script), and `status.ai` (AI).

`nav.step` (`Step {{n}}: {{label}}`) and `nav.done` make up the sidebar's accessible names. Keep the `{{n}}` and `{{label}}` placeholders when you change them.

## Glossary

Every Hindi and Telugu string uses these terms. `tests/i18n-coverage.test.ts` fails when a key used in `web/src` is missing from any language, when placeholders differ, or when a Hindi or Telugu value is still English (outside the allowlist below).

Keep in Latin script, untranslated: Profyn, AI, CSV, JSON, CM1, CM2, CM3, ₹, COD, UPI, Shopify, Meta Ads, Google Ads, Shiprocket,
Razorpay, Markdown, PDF, API, URL, SKU, GST, ID, also file names / code identifiers (e.g. decision-{{id}}.json, order_id, refund_inr).
Placeholders like {{n}}, {{count}}, {{inr}} must be copied EXACTLY (same names, same count). Keep the "·", "—", "→", "−", "=" symbols.
Formulas like "net revenue = revenue − refund": translate the words, keep the symbols.
